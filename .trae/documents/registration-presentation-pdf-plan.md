# 报名报告信息、PDF 与数据备份修补计划

## Context

截图确认后台目前仅有朱建州一条报名记录。现有服务把全部状态放在运行实例的临时目录 `/tmp/tdlee100-state/state.json`，重新部署或实例替换可能重置数据；项目中没有历史名单、回收站或备份。因此孙龙昌、全浩男的完整记录若旧实例已释放，无法仅凭姓名恢复，需要本人重新报名。

本次需要补齐：注册时选择是否报告；选择报告时填写题目和摘要；登录后可修改；可提交小 PDF；本人和管理员可查看/下载；后台也能看到此前已收集但未展示的备注。同时增加管理员完整备份/恢复，降低以后部署造成的数据损失。

## 实施方案

### 1. 后端数据与现有记录兼容

修改 `/workspace/server.js`：

- 为非管理员用户增加 `presentation`：`requested`、`title`、`abstract`、`pdf`；PDF 元数据只保存服务端 ID、原文件名、大小和更新时间，不向前端暴露磁盘路径。
- `loadState()` 为旧账号补默认报告字段，保留原有账号、密码哈希、备注等内容；将状态写入改为临时文件后原子重命名，文件损坏时不得静默覆盖为种子数据。
- 扩展 `publicUser()` 和 `/api/admin/registrations`，返回本人/后台所需的报告信息、备注和 PDF 元数据，但不返回密码哈希、salt 或文件路径。

### 2. 报告信息与小 PDF API

- 扩展 `POST /api/register`，接收是否报告、题目、摘要和可选 PDF；选择报告时题目、摘要必填。
- 新增本人 `PUT /api/me/presentation`，允许登录后修改是否报告、题目和摘要，并支持上传、替换或删除 PDF。
- 新增 `GET /api/registrations/:id/pdf`，仅本人或管理员可下载；其他用户和未登录请求拒绝访问。
- 沿用现有 JSON `api()`/`readJson()`，PDF 以 base64 放入 JSON，避免自行解析 multipart。限制解码后最大 2 MiB、请求体最大 3 MiB；检查扩展名、MIME、严格 base64 和 `%PDF-` 文件头。
- PDF 二进制写入状态目录下的 `uploads/`，文件名使用服务端 UUID；下载按用户记录和文件 ID 查找，禁止客户端传入路径，并设置 `nosniff`、`no-store` 和安全的下载文件名。

### 3. 管理员完整备份与恢复

- 增加仅管理员可用的完整导出/导入：包含用户及原密码哈希、报告字段、备注、PDF 和其他站点状态，PDF 在备份文件中以 base64 表示。
- 导入时验证结构、大小和文件类型，先完整校验再原子替换状态与附件；不得在导入失败时清空现有数据。
- 后台提供明确的导出、导入按钮及敏感数据提示，备份文件不进入公开静态目录或代码仓库。
- 此功能用于以后部署前备份、部署后恢复。此次新功能尚未上线，无法 retroactively 备份旧实例；发布前只能记录当前可见的一条基本信息，不能伪造其密码或恢复旧两人的完整资料。

### 4. 注册、个人修改与后台界面

修改 `/workspace/public/index.html`、`/workspace/public/app.js`、`/workspace/public/styles.css`：

- 注册表单增加“是否报告”选择；选择“是”时显示并启用题目、摘要和 PDF，选择“否”时隐藏、禁用并清空相关输入。
- 登录后的账号面板增加报告信息编辑区、PDF 选择/替换/删除和已有文件下载；复用现有 `api()`、Bearer token、`esc()`、toast 和错误处理。
- 扩展 PDF 下载请求以接收 Blob，再用临时对象 URL 下载，不把登录 token 拼进 URL。
- 后台报名表格增加备注、是否报告、题目、摘要和 PDF 下载；长摘要使用可展开区域，更新空表列数及移动端横向滚动样式。
- 所有动态文本做 HTML 转义；服务端仍做必填、权限和文件校验，不依赖前端限制。

### 5. 十二种语言

在 `/workspace/public/i18n.js` 的 zh/en/fr/ru/de/it/es/ko/ja/ur/fa/ar 中同步新增同一组键：报告选择、题目、摘要、PDF 选择/替换/删除/下载、保存结果、备份/恢复、后台新列及相关错误。保持键集完全一致，并检查 RTL 与移动端布局。

## 验证与发布

1. 执行三个 JavaScript 文件的 `node --check`，验证 12 语言键集一致。
2. 用隔离的临时状态验证：旧账号迁移不清字段；注册报告是/否校验；登录后修改；合法 PDF 上传、替换和本人/管理员下载；超限、伪造 PDF、跨用户及未登录访问均被拒绝。
3. 验证完整备份→清空→恢复后，账号原密码仍可登录、报告字段和 PDF 保持一致；损坏备份不会覆盖现有状态。
4. 重新部署前明确提示：孙龙昌、全浩男需要重新报名；当前仅剩的朱建州账号也无法从旧实例完整迁移，需重新注册。只有用户接受这一点后才执行线上发布，避免未经确认再次清空现存记录。
5. 发布时沿用原 FunctionWeb 站点，确认终端成功后生成一次部署卡片。
